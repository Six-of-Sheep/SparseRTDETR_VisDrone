## CPU CI and platform contract

`python -B tools/check_research_ci.py` runs the explicit 19-file test set for SQC,
R27/L0, R28 and launch locks under CPU-only torch on Linux. Python 3.10 and 3.12
run in GitHub CI. Missing suites, failures, skips or CUDA initialization fail CI.
Dependencies: `environment/requirements-research-ci.txt`. Inputs are synthetic;
no laboratory data, trained checkpoint, detector training or full evaluation is
run. This is additional engineering evidence, not scientific acceptance.

PR checks cover main and stack bases. Workflow changes on this supplementary
branch do not retroactively add jobs to the frozen heads of #35-#38.

Windows supports inspection and the portable unit checks, not Linux launches:

- Real launch locks still use `fcntl.flock`. Imports are deferred until launch,
  so read-only helpers need no no-op lock shim. On Windows lock acquisition fails
  before creating a lock file. Linux tests check exclusion and release.
- MANIFEST keys use `/` on every OS; Linux-generated bytes are unchanged.
- RSS/PSS sampling requires Linux `/proc`; unsupported platforms raise instead
  of silently reporting zero memory use.
- SQC's historical initialization SHA remains unchanged. CPU torch 2.8 on local
  Linux reproduces it; Windows CPU torch 2.8 does not. Linux CI requires exact
  reproduction. Windows checks that a differing state is rejected. This does not
  identify the low-level numerical cause or certify Windows for historical runs.
