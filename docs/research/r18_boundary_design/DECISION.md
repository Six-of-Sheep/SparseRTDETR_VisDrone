# R18边界计算路径设计决定

日期：2026-10-26。状态：**审查两个候选，候选二完成最小CPU读出原型；本轮均不保留，不进入GPU探索。** 这是两条明确路径的淘汰决定，不是断言R18不存在可改进方法。没有追加PR23缓存分析，也没有要求先证明收益或确定唯一训练根因。

## 1. 问题与已有约束

研究问题是“小目标已有中等IoU框，但高IoU几何支持不足”。[PR23固定结果](https://github.com/Six-of-Sheep/SparseRTDETR_VisDrone/blob/dca0f23760166f70653e574e77a6091a9ba77430/docs/research/r18_baseline_evidence/DECISION.md)第7节认证10503个有.50、无.75任意类别几何支持的小GT；仅中心可修3175、仅尺寸可修2866、各自均可1038、各自均不可3424。类别宏平均不支持普遍中心主导。它们是GT辅助固定框配对，不是检测匹配、AP增益、学习可修复性或训练根因。

本轮只引用这些结论。P的采样下限、H2的受限中心路径、排序配方及其失败不重开。混合敏感性要求设计能够表达适当的几何变化，但**不要求新增联合回归模块**：移动一条边本身就同时改变中心和尺寸。

只审查两条路径：

|候选|拟检验的路径|最接近常规控制|决定与具体原因|
|---|---|---|---|
|A：四边局部特征→分桶→桶内偏移|从方向性边界证据而非单个四数向量定位边|同输入、同监督的SABL式边界头|淘汰：拟议核心路径已经由SABL给出，R18接线/去掉重评分不形成方法增量|
|B：相对两边联合分布→期望框|借显式相关性协调中心与尺寸|四边独立分布积分；另设同参数的乘积边缘读出控制|CPU后淘汰：在本方案监督与读出下，固定边缘分布的相关性变化不进入框或损失；未落实所声称的联合信息利用|

## 2. 坐标与接线约定

以下是供审查的计算规格，未装入生产模型。归一化连续图像坐标，x向右、y向下；框为`(cx,cy,w,h)`，边为`L=cx-w/2,R=cx+w/2,T=cy-h/2,B=cy+h/2`。特征采样以实际H/W换算，双线性、零填充、align_corners=False；不把特征上采样称为新增原生细节。

共同输入为第三decoder层query `q3`、最细层特征 `F0`、第二层参考框 `r2`。方向性特征来自以`sg(r2)`为中心、长宽1.5倍的7×7 RoI双线性样本，沿正交方向聚合为一维特征；sg表示stop-gradient。1.5、7和下文8桶仅固定审查实例，不是扫描结果。所有query都计算，不能在推理中使用GT小目标标记、oracle配对或只挑成功框。

[原N冻结decoder](https://github.com/Six-of-Sheep/SparseRTDETR_VisDrone/blob/a97e1eaf750c69c4ee72af232d07632b1aced931/vendor/rtdetrv2_pytorch/src/zoo/rtdetr/rtdetrv2_decoder.py#L258)实际有两条不同通路：采样参考/位置编码用`ref_points_detach`；训练时第2/3层返回框的加法参考使用未detach的`ref_points`（L267–282）。不能笼统称“层间框梯度全部截断”。以下额外RoI坐标始终detach；若候选将来生产化，必须分别登记输出基准框的梯度，不能以采样detach代替整个梯度审查。本轮只实施B的分布读出核，不声称完成R18/aux/DN/EMA生产接线。

## 3. 候选A：四边分桶及局部偏移

### 输入、公式与监督

用RoI方向特征`f_s`预测每边8个bucket logits `a_sk`和桶内偏移`d_sk`。桶中心`x_sk`由扩展后的参考区域确定，间距`Δ_s`。推理取`k*=argmax_k a_sk`（完全并列取最小k），输出：

`b_s = x_s,k* + Δ_s d_s,k*`，`c_x=(b_L+b_R)/2`，`w=b_R-b_L`，纵轴同理。

训练只对原Hungarian匹配正query及有GT对应的有效DN项监督：最近桶为正、第二近桶不作负分类，两最近桶监督归一化偏移`(g_s-x_sk)/Δ_s`。分类用二元交叉熵，偏移用SmoothL1；原类别监督仍来自检测GT。没有额外语义/轮廓标注；GT只在训练使用。推理不重评分、不NMS、不以GT选边。

最近桶的监督选择不反传；分类梯度到边分类头/方向特征/F0，偏移梯度到相应回归头/F0；RoI坐标不向r2反传。argmax不可导，不能声称最终框loss通过argmax训练桶选择。早层原aux、DN分组和padding掩码必须保留，不能对padding造GT。未增加新的生产loss配置，此段只是被否决方案的定义。

两边移动量`δL,δR`对应`δcx=(δL+δR)/2,δw=δR-δL`，能同时表达平移和缩放，无须先决定“中心错还是尺寸错”。但独立选边可能跨到不同邻近物体，甚至形成反向边；遮挡、边界模糊、GT超出搜索域和低分辨率混叠均会失败。不能靠GT在推理期排除这些情况。

### 直接先例与淘汰

[SABL原文§3.1–3.2、图2–3](https://www.ecva.net/papers/eccv_2020/papers_ECCV/papers/123490392.pdf)已给出方向特征、边界分桶及桶内回归，含最近/次近桶标签处理。本方案所希望利用的整体机制与之重合。RoI双线性是已有算子；改为R18 query入口、改桶数/采样尺寸、删除其重评分，均不提供新的可检验机制。

[LocNet](https://www.cv-foundation.org/openaccess/content_cvpr_2016/papers/Gidaris_LocNet_Improving_Localization_CVPR_2016_paper.pdf)更早已有搜索域内按行列预测边界概率的框定位路径；本次仅用已读概要与§3.1支持此范围，不推断全部实现等价。

最简单否定控制正是同输入SABL式头；固定相同提取和监督后，A没有剩余干预变量。若相对N有益，也只支持常规边界头在本协议中的适用性，不能支持A的额外价值。**在文献阶段淘汰A，不为它搭CPU或GPU模型。** 这不否定SABL作为未来方法的常规控制。

## 4. 候选B：相对两边联合分布的期望读出

### 精确路径

动机：两边的相对运动共同决定中心和宽度；试图以联合分布保留共现关系，避免各边各自取一个不相容的模式。此动机是设计假设，不是PR23已观察到多峰或边界错配。

横轴用8个固定相对位移`d_i=-1/4+i/14, i=0..7`，纵轴相同。令`h_Li=concat(q3,f_L(i))`、`h_Rj=concat(q3,f_R(j))`；使用共享线性映射`a_i=w_a^T h_Li+b_a`、`u_i=w_u^T h_Li+b_u`，右边同理得到`b_j,v_j`。索引位置由方向特征位置保留，构造秩1相互作用：

`z_ij=a_i+b_j+u_i v_j`，`P_ij=exp(z_ij)/Σ_mn exp(z_mn)`。

`μ_L=Σ_ij P_ij d_i`，`μ_R=Σ_ij P_ij d_j`。

`L = r2.cx-r2.w/2 + sg(r2.w) μ_L`，
`R = r2.cx+r2.w/2 + sg(r2.w) μ_R`；T/B同理。

训练输出基准项保留r2的live梯度，位移尺度与RoI坐标detach；推理只需预测r2。正宽高r2与±1/4支持保证新宽高至少原来一半；允许越出图像，不额外clip。若GT修正超出此支持范围，期望无法达到GT。这是范围限制，不通过扩大范围或现场调参弥补。

监督用原末层类别损失及固定权重的L1/GIoU框损失，Hungarian按预测输出和GT确定（匹配离散选择不反传）；原前两层aux、DN正负身份和padding掩码保留。**不增加联合NLL、蒸馏、分布标签或IoU质量重评分。** 所以本方案不是通过另加一个loss代理制造差异。推理将联合期望转成四数框，类别分支沿用原q3，top预算不变。设计不声称参数量/耗时等于N。

令`g_L=∂loss/∂L,g_R=∂loss/∂R`，单轴logit梯度为：

`∂loss/∂z_ij = sg(w) P_ij [g_L(d_i-μ_L)+g_R(d_j-μ_R)]`。

梯度到联合头/q3/方向特征/F0；通过live基准项到r2，**不通过本次新增采样坐标或位移尺度到r2**。对`u_i`的梯度为`Σ_j(∂loss/∂z_ij)v_j`。一般不为零；不能由下述等价证明说联合头“完全学不到”或所有训练轨迹一样。

### 最近先例、常规控制和拟议差异

[D-FINE v1 §4.1式2–5](https://arxiv.org/html/2410.13842v1#S4.SS1)已采用四边离散分布、按参考宽高缩放的期望偏移及层间分布细化。B没有复现其完整FDR、非均匀支持或GO-LSD，也不把“分布回归用于DETR”作为新意。与A及既有边界方法相比，B唯一拟议机制差异是**相对两边的联合相互作用能否在输出中使用边界共现信息**。秩1双线性和softmax本身是已有运算，不作为贡献。

常规控制C0是相同输入、支持、监督及期望读出的四边独立分布头。C0参数不同，不能只凭B−C0判断相关性贡献，因此先加严格机制控制C1：保留B全部参数和logits，计算其边缘概率后，替换为乘积分布。

`p_L(i)=Σ_jP_ij, p_R(j)=Σ_iP_ij, Q_ij=p_L(i)p_R(j)`。

C1保留两边各自的分布、所有特征和梯度来源，只删掉联合相关性。它是常规独立分布的代数投影控制，不冒充一个已独立训练的C0。没有通过增加C1模型臂把本轮扩展成训练计划。

### 否定结果及其边界

直接代入得：`E_P[d_L]=E_Q[d_L]`、`E_P[d_R]=E_Q[d_R]`。故中心、宽高、四数框、任何只依赖这些框的L1/GIoU及据此产生的匹配均相同。对同一个参数化P，C1与B还是**相同的可微函数**，在可导位置参数梯度相同；L1拐点/匹配并列不由有限差分证明，代数输出等价仍成立。

更明确地，对任意每行/每列和为零的合法扰动`ΔP`，框坐标和该监督完全不变。于是B所称“共现信息帮助选择协调边界”的信息没有被本期望读出使用。多峰的期望仍可能落在两个模式之间。

这只否定**固定边缘分布后相关性经此读出发挥额外作用**。双线性参数也可能改变边缘分布和优化；不能推成B与另建独立头C0的函数类、参数梯度或训练轨迹等价，更不能证明B不可能涨点。但那样的涨点不能凭此设计解释为利用联合相关性。现有方案没有留下区别于更复杂边缘预测头的明确机制检验对象，因此不以增加参数后的潜在收益作为保留依据。

联合NLL、联合MAP、非线性风险最小化可以打破本证明的前提，CPU也专门保留NLL反例。**本轮没有审查或否决这些全部扩展，也不把它们临时补成第三候选。** 它们需要各自的监督、可导路径、直接先例和控制，不能用“改成联合”三个字自动修复方案。

## 5. 唯一CPU原型及正反例

[tools/r18_boundary_design_cpu.py](../../../tools/r18_boundary_design_cpu.py)是B的最小分布读出核与解析梯度检查；不是完整特征网络，不加载检测器、真实缓存、checkpoint、图像或标注，没有训练。用Python标准库执行：

```text
python -B tools/r18_boundary_design_cpu.py
```

十一项检查通过，结果见[CPU_RESULT.json](CPU_RESULT.json)，全部标记`SYNTHETIC_NOT_SCIENTIFIC`：

1. 多组联合概率与乘积边缘控制输出相同。
2. 合法两边坐标L={0,2}、R={4,6}，联合概率(.4,.1,.1,.4)与(.1,.4,.4,.1)协方差分别+.6/−.6，输出均L=1、R=5，坐标损失相同。
3. 固定边缘的相关性扰动不改变框与损失。
4. softmax解析梯度与中心有限差分一致，最大误差约1.82e−11；B与C1梯度一致。
5. 一般logit梯度非零，保留“参数改变边缘分布仍可影响框”的反例。
6. 正例：修正一条错误边可同时修正中心和宽度，提升构造框IoU，不必额外建中心/尺寸联合模块。
7. 反例：两模式(0,4)/(2,6)的期望(1,5)对GT(0,4)仅IoU .6；联合期望没有自动避免平均到两模式之间。
8. 有限支持不能恢复范围外边界。
9. 对指定联合事件的NLL在两同边缘分布间不同，证明不能把等价结论推广至所有联合监督。

另核验秩1相互作用参数的链式梯度，以及零相互作用时退化为独立分布的常规控制，共十一项。最小原型采用2×2支持，等价推导适用于任意桶数；未测试完整8桶特征头。

平方坐标损失仅作平滑数值梯度证人，并未替换提议中的L1/GIoU；任意框函数等价由代数式证明。本测试没有自动微分、全模型匹配/aux/DN/EMA接线验收或优化轨迹试验。CPU通过确认计算和反例成立，不是局部机制在真实模型中成立，更不是检测质量通过。

## 6. 分阶段进入规则与本轮决定

本轮第0阶段是路径差异与可否定控制：A在原文对照淘汰；B在唯一CPU原型的C1控制下，核心相关性读出主张被代数否定。**没有保留候选，故下一阶段GPU预算为0，也没有待启动两臂/三臂e120。** 不以“根因不确定”或“还没有收益”否决它们：A缺少相对已有整体机制的干预变量，B的拟议信息在明确读出中被边缘化消去。

若未来另行授权重新设计，进入有预算探索前应先满足一个具体条件：在固定边缘分布、特征和其他路径时，拟议计算确实能按明确定义的信息差异改变框决策，且不是已有整体机制的同义复述；或者提出与本轮两条路径不同且同样可控的干预。无需先查明N训练根因，也不必提前证明e120收益。本轮不再追加终点缓存统计来满足这个条件。

只有有明确保留候选时，才制定匹配的短探索上限、模型对照、数据/终点和进入完整训练条件。短窗可以排除数值/接线问题，或在冻结输入上检验定义的局部机制；不能可靠外推e120检测收益、替代正式质量裁决或据此选最佳配方。此处不为被淘汰方案编造GPU小时或安排训练来“再看看”。
