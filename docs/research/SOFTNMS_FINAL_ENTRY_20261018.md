# Final entry and explicit reuse certification

The dispatcher now uses distinct names for all branch-local imports. Static
binding checks cover every import in main and require supervise to resolve to
the module function. No loss, prediction, suppression, evaluator or gate changes.

Final acceptance invokes the deployed softnms_score_launch.py itself. Its
synthetic request supplies only four named synthetic images and three synthetic
seeds. The same run CLI, actual supervisor, actual worker process, journal,
original dual evaluators, RESULT/CLOSED writer, exporter and process exit paths
are exercised. The launcher waits for and records the actual supervisor exit.
A separate case deliberately raises in the actual worker; the supervisor must
reject it, preserve STOP, export and exit. Both the actual launcher and run CLI
must reject consumed success output without changing its files. No supervisor,
pipeline or evaluator is replaced by a test double.

The synthetic backend is explicitly scoped, uses only paths under its synthetic
suite and authenticates its context and input files. It cannot accept the real
548 members or production references. Synthetic scores are engineering evidence.

Reuse keeps the original revision006 gate files and source unchanged. A separate
interpreter imports its original verifier from the original frozen source,
executes its strict source/contract/gate checks and verifies the existing E/D
prediction hashes, identities and membership. It does not rebuild raw caches,
infer or score. A new certificate binds that receipt to the new source manifest.
Every original file is checked; only enumerated entry/fixture/CI changes are
permitted. The job module AST must remain identical outside the five explicitly
listed lifecycle functions. The old fixture calculation must remain identical
after removing its new build-only return. Scientific core, data, evaluators and
frozen configuration remain byte-identical. New source is independently checked
against its own complete manifest; no old SHA is compared to new bytes, ignored
or rewritten. Parent, checkpoint, context, rows and prepared references must
remain identical at scientific startup.

Only a CPU gate tied to the final deployed manifest permits a new scoring
contract. Worker-start evidence is separate from score events; a launch receipt
alone does not establish that scientific scoring is running. A scientific
exception STOPs without retry. Quality uses the original fixed gates, and a
quality PASS still leaves end-to-end cost unverified. Results, failures and exact
run identities are recorded separately in revision007 delivery.
